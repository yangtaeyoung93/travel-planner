# harness-orchestrator skill

`harness-design`으로 정한 팀을 **어떤 순서로, 어떤 판정으로, 어디까지 재시도하며** 돌릴지 쓴다.

## 구현 방식 고르기

| 방식 | 인계 수단 | 이 프로젝트 예시 |
|---|---|---|
| 스킬 | `_workspace/*.md` 파일 | `commit-message` |
| 워크플로우 스크립트 | 스키마로 받은 반환값 | `eastern-europe-package-research.js` |

팀이 2~3명이고 루프가 단순하면 스킬, 대상이 많고 병렬·재확인이 필요하면 스크립트를 쓴다.

## 작성 순서

1. **사전 점검**: 입력이 없거나 비면 실행하지 않고 사용자에게 알린다.
2. **호출**: 프롬프트에 저장 경로와 "반드시 Write로 저장"을 적는다. 서브에이전트는 요청받지 않으면 파일을 만들지 않는다.
3. **판정 병합**: 판정 파일 첫 줄이 `PASS`일 때만 통과다. 파일이 없거나 형식이 불명확하면 REDO다.
4. **재시도**: REDO 사유를 다음 호출 프롬프트에 넣는다. 상한은 2회로 둔다.
5. **상한 초과**: 마지막 결과를 "수동 검토 권장" 경고와 함께 보이고 끝낸다.
6. **종료 보고**: 결과 파일 경로, 통과 여부, 재시도 횟수만 알린다. 중간 산출물은 대화에 싣지 않는다.

## 병렬화 범위

- 공유 자원(브라우저, DB)을 쓰는 단계만 직렬로 잠근다. 나머지는 병렬로 돌린다.
- 예: 동유럽 조사는 여행사별 검색은 병렬, 브라우저 검증은 직렬, 분석은 병렬이다.
- 재확인은 질문이 나온 대상만 한다. 전체를 다시 돌리지 않는다.

## 부분 실패

- 실패한 작업자만 빼고 계속하고, 실패 목록을 보고서에 남긴다.
- 재평가가 실패하면 직전 평가를 그대로 쓴다.
- 결과가 하나도 없으면 중단하고 원인(연결, 네트워크)을 알린다.

## 흔한 실수

| 실수 | 해결 |
|---|---|
| 판정 파일이 없는데 통과 처리 | 없으면 REDO로 처리한다 |
| 재시도에 상한이 없음 | 상한과 초과 시 동작을 먼저 쓴다 |
| 모든 단계를 직렬로 처리 | 공유 자원 단계만 직렬로 잠근다 |
| 한 작업자 실패로 전체 중단 | 실패를 격리하고 목록으로 남긴다 |
